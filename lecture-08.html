Огляд CSS-фреймворків: Tailwind CSS, Bootstrap

У темі 7 ми власноруч писали кожне правило: скидання box-sizing, сітку карток, медіазапити. Для навчання це єдиний правильний шлях, але в реальному проєкті ті самі задачі повторюються щоразу: кнопки, форми, меню, сітка з 12 колонок, точки перелому. CSS-фреймворк — це готовий, перевірений набір таких рішень: файл стилів (іноді разом зі скриптами) і домовленості про назви класів. Ви підключаєте його й одразу користуєтеся класами замість того, щоб писати CSS з нуля.

Що дає фреймворк: швидкий старт і прототипування; узгоджений вигляд усіх елементів; продумані точки перелому й сітку; документацію, за якою працює вся команда. Чим за це платять: сайти стають схожими один на одного, у проєкті з’являється залежність від чужого коду та його версій, а розмітка обростає класами. І головне застереження: фреймворк не скасовує знання CSS. Щойно вигляд треба змінити не так, як передбачили автори, без розуміння каскаду, специфічності й Flexbox/Grid з теми 7 не обійтися.

Сьогодні найчастіше говорять про два фреймворки з протилежною філософією (рис. 1). Bootstrap — компонентний: ви пишете class="card" чи class="btn btn-primary" і отримуєте готовий компонент. Tailwind CSS — утилітарний (utility-first): готових компонентів немає, а є сотні дрібних класів, кожен з яких робить одну річ (p-6 — внутрішній відступ, rounded-xl — заокруглення, text-white — колір тексту), і вигляд ви складаєте з них просто в HTML.

Bootstrap. Фреймворк створили Марк Отто (Mark Otto) і Джейкоб Торнтон (Jacob Thornton) у компанії Twitter; першу версію оприлюднили в серпні 2011 року. Бібліотека JavaScript jQuery, без якої колись не обходився Bootstrap, з п’ятої версії (2021) більше не потрібна. Актуальна стабільна версія станом на жовтень 2026 року — 5.3.8. 8 жовтня 2026 року вийшла перша альфа-версія Bootstrap 6, але автори прямо попереджають, що до бета-версії в ній ще можуть суттєво змінитися речі, тож для реальних проєктів і для навчання беремо 5.3.

Як підключити. Найпростіше — через CDN (мережу доставки вмісту): у <head> додають посилання на стилі, а перед </body> — скрипт. Файл bootstrap.bundle.min.js уже містить бібліотеку Popper, потрібну для випадних меню, підказок і спливних вікон. Атрибут integrity — це контрольна сума файлу: браузер перевірить, що файл на CDN ніхто не підмінив. Для кожної версії вона своя, тому посилання копіюйте з документації цілком.

  crossorigin="anonymous">

Сітка Bootstrap побудована на Flexbox і працює за принципом mobile-first, який ви знаєте з теми 7. Три рівні вкладеності: .container центрує вміст і обмежує його ширину; .row — рядок, обгортка для колонок; .col-* — колонки. У рядку 12 колонок, і число в класі показує, скільки з них займає блок: col-4 — третину, col-6 — половину. Інфікс точки перелому означає «від цієї ширини й більше»: col-12 col-md-6 col-lg-4 — на всю ширину на телефоні, половина від 768px і третина від 992px (рис. 2). Проміжки між колонками задають класи g-* (наприклад, g-4).

<div class="container">
  <div class="row g-4">
    <div class="col-12 col-md-6 col-lg-4">
      <article class="card h-100">
        <div class="card-body">
          <h3 class="card-title h5">Тариф «Старт»</h3>
          <p class="card-text">Лендинг на 5 блоків і хостинг на рік.</p>
          <a href="#order" class="btn btn-primary">Замовити</a>
        </div>
      </article>
    </div>
    <!-- ще дві такі колонки -->
  </div>
</div>

Точки перелому Bootstrap 5.3: без інфікса — менше 576px; sm — від 576px; md — від 768px; lg — від 992px; xl — від 1200px; xxl — від 1400px. Крім сітки, Bootstrap має десятки компонентів (навігаційна панель navbar, картки, кнопки, форми, модальні вікна, акордеон) і утиліти — дрібні допоміжні класи на кшталт mt-3 (відступ зверху), d-flex (Flexbox), text-center. Приклади в документації вже містять потрібні ARIA-атрибути (aria-expanded, aria-label тощо) — копіюючи компонент, не видаляйте їх: від них залежить, чи зрозуміє меню екранний читач.

Tailwind CSS. Утилітарний фреймворк від компанії Tailwind Labs. Четверта версія вийшла в січні 2025 року, актуальна — 4.3 (травень 2026). Головна ідея: замість того, щоб вигадувати назву класу (.price-card) і переходити в CSS-файл, ви одразу пишете властивості в розмітці короткими класами. Інструмент Tailwind сканує ваші файли й генерує CSS лише для тих класів, які ви справді використали. Для картки з рис. 1 вийшов файл стилів на 7,6 КБ, тоді як повний bootstrap.min.css важить близько 230 КБ (наші вимірювання для версій 4.3.3 і 5.3.8; зі стисненням gzip — приблизно 2 КБ проти 31 КБ).

Як підключити. Для першого знайомства є Play CDN — скрипт, який генерує стилі просто в браузері. Документація наголошує: він призначений лише для розробки, не для робочого сайту. У реальному проєкті Tailwind встановлюють через npm і запускають у режимі спостереження: інструмент перебудовує CSS щоразу, коли ви зберігаєте файл.

<!-- лише для навчання й прототипів -->
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>
# робочий спосіб: Tailwind CLI
npm install tailwindcss @tailwindcss/cli
npx @tailwindcss/cli -i ./src/input.css -o ./src/output.css --watch

Файл input.css у четвертій версії складається з одного рядка @import "tailwindcss";. Налаштування (власні кольори, шрифти, точки перелому) тепер задають у самому CSS директивою @theme, а не в окремому файлі tailwind.config.js, як у версії 3 — пам’ятайте про це, коли натрапите на старі уроки. Кожна змінна з @theme одразу стає класом: --color-brand дає bg-brand, text-brand, border-brand.

@import "tailwindcss";

@theme {
  --color-brand: #1d4ed8;
}
<article class="max-w-sm rounded-xl border border-slate-200 bg-white p-6 shadow-sm">
  <h3 class="text-xl font-semibold text-slate-900">Тариф «Старт»</h3>
  <p class="mt-2 text-slate-600">Лендинг на 5 блоків і хостинг на рік.</p>
  <a href="#order" class=mt-4 inline-block rounded-lg bg-brand px-4 py-2
     font-medium text-white hover:bg-blue-800>Замовити</a>
</article>

Адаптивність у Tailwind теж mobile-first: клас без префікса діє на всіх ширинах, а з префіксом — від точки перелому й більше. Типові точки: sm — 40rem (640px), md — 48rem (768px), lg — 64rem (1024px), xl — 80rem (1280px), 2xl — 96rem (1536px). Запис grid gap-6 md:grid-cols-2 lg:grid-cols-3 означає: один стовпець на телефоні, два від 768px, три від 1024px. Документація окремо застерігає: не використовуйте sm:, щоб націлитися на телефон. Читайте sm: як «від малої точки перелому», а не «на малих екранах». Стан наведення й фокусу задають так само, префіксами: hover:, focus-visible:.

Сумісність. Tailwind 4 спирається на сучасні можливості CSS і працює в Chrome від 111, Safari від 16.4 і Firefox від 128. Якщо сайт мусить відкриватися в старіших браузерах, документація радить залишитися на версії 3.4. А ось зі старими браузерами Bootstrap 5.3 почувається впевнено — у цьому одна з причин, чому його досі обирають для корпоративних систем.

Як обрати. Якщо потрібен робочий інтерфейс за день — адмінпанель, внутрішня система, прототип для замовника, — Bootstrap дасть готові компоненти. Якщо у вас є власний макет у Figma (тема 4) і важливо відтворити саме його, зручніший Tailwind. Якщо сайт невеликий, а ви добре знаєте CSS — цілком можливо, що фреймворк не потрібен узагалі: сучасні Flexbox, Grid і CSS-змінні закривають більшість задач. 02

Препроцесори Sass/SCSS: змінні, міксини, вкладеність

Препроцесор CSS — програма, яка перетворює («компілює») код, написаний розширеною мовою, у звичайний CSS. Браузер про препроцесор нічого не знає: він отримує лише готовий файл .css. Найпоширеніший препроцесор — Sass (Syntactically Awesome Style Sheets). Його створили Гемптон Кетлін (Hampton Catlin) і Наталі Вайценбаум (Natalie Weizenbaum) у 2006 році. Офіційно назву пишуть Sass — не «SASS»: це слово, а не абревіатура.

Два синтаксиси. Sass має синтаксис SCSS (файли .scss) — з фігурними дужками й крапками з комою, як у CSS. Будь-який коректний CSS-файл уже є коректним SCSS, тож перехід безболісний. Старіший відступний синтаксис (файли .sass) обходиться без дужок і крапок з комою — структуру задають відступи. У цій лекції й на практичних ми використовуємо SCSS.

Компілятор. Основна й рекомендована реалізація — Dart Sass (актуальна версія — 1.105.1). LibSass і пакет node-sass, які досі трапляються в старих уроках, застаріли й більше не розвиваються. Встановити Sass можна через npm (потрібен Node.js) або завантажити окрему програму зі сторінки релізів Dart Sass на GitHub. Ключ --watch змушує компілятор стежити за файлами й перекомпільовувати CSS після кожного збереження (рис. 3).

npm install -g sass
sass --version
# одноразова компіляція
sass scss/main.scss css/style.css
# компіляція після кожного збереження
sass --watch scss/main.scss css/style.css

Змінні. Змінну оголошують знаком $: $brand: #1d4ed8;. Змінюєте значення в одному місці — і нове значення з’являється скрізь, де змінну використано. Важливо розуміти відмінність від CSS-змінних (--brand), які ви вже бачили: змінна Sass існує лише під час компіляції й у готовому CSS перетворюється на звичайне значення, а CSS-змінна живе в браузері — її можна змінити медіазапитом, класом .dark чи скриптом. Тому для тем оформлення (світла й темна) обирають CSS-змінні, а змінні Sass — для сталих налаштувань проєкту: точок перелому, розмірів сітки, базових кольорів.

Вкладеність (nesting). Правила можна вкладати одне в одне, повторюючи структуру HTML. Символ & означає «батьківський селектор»: &:hover всередині .card дає .card:hover, а &__title — .card__title (зручно для іменування за методологією BEM). Документація Sass застерігає від надмірної вкладеності: вона породжує задовгі селектори з високою специфічністю, які важко перевизначити. Практичне правило — не глибше трьох рівнів.

Вкладеність тепер є і в чистому CSS. Починаючи з грудня 2023 року всі основні браузери підтримують нативну вкладеність CSS, і MDN позначає її як Baseline (широко доступна). Але є різниця: чистий CSS не склеює частини назв, тож запис &__title працює лише в Sass. Сама по собі вкладеність уже не є причиною брати препроцесор — нею стали модулі, міксини й цикли.

Частини файлів (partials) і модулі. Великі стилі ділять на файли: _variables.scss, _mixins.scss, _header.scss. Підкреслення на початку назви означає частину (partial): Sass не створює з неї окремого CSS-файлу. Частини підключають правилом @use, і все, що в них оголошено, доступне через простір імен — за замовчуванням це назва файлу без підкреслення: variables.$brand. Коротше ім’я задають через as: @use "variables" as v; → v.$brand. Правило @forward дозволяє зібрати кілька частин в одну «точку входу» для бібліотеки.

Обережно: @import застарів. У багатьох уроках в інтернеті частини підключають правилом @import. Починаючи з Dart Sass 1.80.0 воно позначене як застаріле: компілятор виводить попередження, а у версії Dart Sass 3.0.0 правило буде вилучено. У нових проєктах використовуйте лише @use і @forward; для переведення старого коду є офіційна утиліта sass-migrator. Застарілими вважаються й глобальні функції на кшталт darken() чи lighten() — їм на зміну прийшли функції модулів sass:color і sass:math.

// _variables.scss — дизайн-токени проєкту
$brand: #1d4ed8;
$ink: #1e293b;
$radius: 12px;
$bp-md: 48rem;
$themes: (
  it: #1d4ed8,
  law: #7c2d12,
  marketing: #be185d,
);

Міксини. Міксин — іменований фрагмент оголошень, який вставляють у різні правила. Його оголошують через @mixin, вставляють через @include, і він може приймати параметри зі значеннями за замовчуванням. Директива @content дозволяє передати в міксин цілий блок правил — так зручно оформити медіазапит mobile-first із теми 7 один раз і користуватися ним скрізь.

// _mixins.scss — повторювані фрагменти
@use "variables" as v;

@mixin from($bp) {
  @media (min-width: $bp) {
    @content;
  }
}

@mixin button($bg: v.$brand) {
  display: inline-block;
  padding: 0.6rem 1.2rem;
  border-radius: v.$radius;
  background: $bg;
  color: #fff;
  text-decoration: none;
}

Цикли й мапи. Мапа (map) — набір пар «ключ: значення», як $themes вище. Цикл @each перебирає її і генерує однотипні правила, а запис #{$name} (інтерполяція) вставляє значення змінної просто в назву селектора. Нижче — головний файл, який збирає все разом; на рис. 4 видно, що з нього отримує браузер.

// main.scss — точка входу, компілюється в css/style.css
@use "variables" as v;
@use "mixins" as m;

.card {
  padding: 1.5rem;
  border-radius: v.$radius;
  color: v.$ink;
  &__title { font-size: 1.25rem; }
  &:hover { box-shadow: 0 4px 16px rgb(0 0 0 / 0.12); }
  a { @include m.button; }
}

.cards {
  display: grid;
  gap: 1.5rem;
  @include m.from(v.$bp-md) {
    grid-template-columns: repeat(2, 1fr);
  }
}

@each $name, $color in v.$themes {
  .badge--#{$name} { background: $color; }
}

Зверніть увагу на кілька деталей результату. Частини _variables.scss і _mixins.scss окремих CSS-файлів не дали. Міксин from розгорнувся в звичайний @media, а @each створив три класи .badge--it, .badge--law і .badge--marketing — по одному для кожної спеціальності. Коментарі // у CSS не потрапляють (на відміну від /* */). Ще одна корисна функція — color.adjust() із модуля sass:color: color.adjust($brand, $lightness: -10%) обчислює темніший відтінок під час компіляції. У готовому CSS такий колір може з’явитися як rgb() із дробовими відсотками — це нормальний, валідний запис.

Препроцесор і фреймворки. Bootstrap написаний на Sass, і саме так його глибоко налаштовують: підключають вихідні файли й підміняють змінні. Bootstrap 5.3 ще всередині використовує @import, тому компілятор покаже кілька попереджень про застарілість — це не ваша помилка, а ключ --quiet-deps приховує попередження із залежностей. У Bootstrap 6 автори вже перейшли на @use і @forward. А от Tailwind 4, за власною документацією, не призначений для роботи разом із Sass: він сам виконує роль препроцесора (імпорти, вкладеність, змінні).

// власний колір Bootstrap (потрібен пакет bootstrap з npm)
@use "bootstrap/scss/bootstrap" with (
  $primary: #7c2d12
);
npm install bootstrap@5.3.8
sass --load-path=node_modules --quiet-deps scss/custom.scss css/custom.css
ТЕСТ 2 Модулі @use✓
У файлі _variables.scss оголошено $brand: #1d4ed8;, а файл main.scss починається рядком @use "variables";. Як звернутися до кольору в main.scss?
03

Публікація сайту: GitHub Pages, Netlify, Vercel

Сайт, який відкривається лише з вашого диска, бачите тільки ви. Публікація (деплой, deploy) — розміщення файлів на сервері, доступному з інтернету, під постійною адресою. Усі сторінки, які ми створюємо в курсі, — статичні сайти: HTML, CSS, зображення й, можливо, JavaScript, які сервер віддає браузеру без змін. Для таких сайтів не потрібен власний сервер чи платний хостинг: є сервіси, що безкоштовно публікують статичні файли, автоматично вмикають HTTPS і розносять копії сайту по серверах у різних країнах (CDN), щоб сторінка швидко відкривалася будь-де.

Що саме публікують. На сервер потрапляє те, що читає браузер: HTML, скомпільований CSS, зображення, шрифти. Файли .scss браузеру не потрібні — їх або не викладають, або доручають компіляцію самому сервісу (це вміють Netlify і Vercel). Головна сторінка має називатися index.html і лежати в корені папки, що публікується.

Чек-лист перед публікацією:

  • відносні шляхи: css/style.css, а не C:/Users/.../style.css — абсолютний шлях до вашого диска на сервері не існує;
  • регістр літер: сервери працюють на Linux, де Style.css і style.css — різні файли; Windows цієї різниці не помічає, тож помилка проявиться лише після публікації. Найпростіше — називати файли й папки малими латинськими літерами, без пробілів і кирилиці;
  • валідний HTML (ПР 13) і тег <meta name="viewport"> (тема 7);
  • заповнені <title> і <meta name="description"> — їх показують пошукові системи й соцмережі;
  • жодних секретів: паролі, ключі доступу та особисті дані клієнтів не повинні потрапити в публічний репозиторій — його вміст бачить кожен.

GitHub Pages — хостинг статичних сайтів просто з репозиторію GitHub. На безкоштовному тарифі репозиторій має бути публічним; сам сайт GitHub Pages завжди публічний. Порядок дій за документацією GitHub:

  • створіть публічний репозиторій (наприклад, webdesign-lecture8) і завантажте в нього файли сайту: Add file → Upload files, або через Git;
  • відкрийте Settings → Pages; у розділі Build and deployment для Source оберіть Deploy from a branch;
  • виберіть гілку main і папку /(root) (або /docs, якщо сайт лежить там) і натисніть Save;
  • зачекайте: за документацією, зміни публікуються протягом до 10 хвилин; посилання Visit site з’явиться на тій самій сторінці.

Адреса проєктного сайту має вигляд https://логін.github.io/назва-репозиторію/. Якщо назвати репозиторій логін.github.io, сайт відкриватиметься просто за адресою https://логін.github.io — це зручно для портфоліо. Обмеження: розмір опублікованого сайту — до 1 ГБ, рекомендований «м’який» ліміт трафіку — 100 ГБ на місяць, а серверні мови (PHP, Python) не підтримуються. За замовчуванням GitHub обробляє сайт генератором Jekyll; якщо він вам не потрібен, додайте в корінь порожній файл .nojekyll. Важливо для майбутніх юристів і маркетологів: GitHub Pages не можна використовувати як безкоштовний хостинг для інтернет-магазину чи комерційного онлайн-бізнесу, а також для сторінок, що приймають паролі чи дані банківських карток.

Netlify пропонує два шляхи. Netlify Drop (app.netlify.com/drop) — найшвидший: перетягніть папку з сайтом у вікно браузера, і за кілька секунд він отримає адресу на домені netlify.app. Документація радить спершу увійти в обліковий запис: тоді сайт закріпиться за вами, і його можна буде оновлювати. Другий шлях — підключити репозиторій Git: після кожного git push Netlify сам збирає й публікує сайт, а для змін створює попередній перегляд (Deploy Preview), щоб перевірити їх до публікації. Безкоштовний план працює на кредитах: 300 кредитів на місяць із жорстким лімітом. За документацією, кожна публікація в робочу версію (production deploy) коштує 15 кредитів, 1 ГБ трафіку — 20 кредитів, 10 000 запитів — 2 кредити. Коли кредити закінчуються, сайт призупиняється до початку наступного місяця.

Порахуймо: 300 ÷ 15 = 20. Лише двадцять публікацій — і місячний ліміт вичерпано, навіть якщо сайт ніхто не відвідував. Тому на безкоштовному Netlify не варто «перезаливати» сайт після кожної дрібної правки: збирайте зміни й публікуйте рідше, а щоденні експерименти перевіряйте локально чи на GitHub Pages.

Vercel працює схоже: імпорт репозиторію з GitHub, GitLab чи Bitbucket — і кожен коміт або pull request автоматично створює окреме розгортання з унікальною адресою; є Vercel Drop (vercel.com/drop) для перетягування папки і консольна утиліта. Безкоштовний план Hobby розрахований на особисті некомерційні проєкти; серед лімітів — до 100 розгортань на день, 100 ГБ трафіку (Fast Data Transfer) на місяць і до 200 проєктів. Якщо ліміт перевищено, здебільшого доводиться чекати 30 днів, доки функція знову стане доступною. Vercel створила фреймворк Next.js і особливо зручна для сайтів на ньому, але статичні HTML-сторінки публікує так само просто.

# публікація з терміналу (після входу в обліковий запис)
npm install -g netlify-cli
netlify deploy --prod

npm install -g vercel
vercel --prod

Ліміти й ціни безкоштовних планів змінюються — наведені дані звірено з документацією сервісів станом на жовтень 2026 року. Перед тим як розміщувати сайт для реального замовника, завжди перечитуйте чинні умови: це вже не технічне, а юридичне питання.

ТЕСТ 3 Стилі зникли після публікації✓
На комп’ютері з Windows сайт виглядав правильно, але на GitHub Pages сторінка відкрилася без стилів. У коді — <link rel="stylesheet" href="CSS/Style.css">, а в репозиторії лежить файл css/style.css. У чому причина?

Де це знадобиться. Посилання на живий сайт — найкраща частина резюме: роботодавець відкриває його з телефона за секунду, на відміну від архіву з файлами. Фахівцю з інформаційних систем Sass, фреймворки й автоматична публікація з Git — щоденні робочі інструменти командної розробки. Юристу знання про те, що публічний репозиторій бачать усі, а безкоштовні плани мають обмеження щодо комерційного використання, допоможе оцінити ризики для клієнта ще до того, як сайт запрацює. Маркетологу Bootstrap чи Tailwind дають змогу за вечір зібрати й опублікувати посадкову сторінку для тестування гіпотези, не чекаючи на розробника.

ЗАВДАННЯ 2 Від SCSS до живого сайту✓
  1. Встановіть Sass (npm install -g sass або окрема програма з релізів Dart Sass) і перевірте командою sass --version. Скопіюйте проєкт lecture7 у нову папку lecture8-site.
  2. Створіть папку scss з файлами _variables.scss (кольори, радіус, точки перелому в rem), _mixins.scss (міксин from($bp) з @content) і main.scss. Перенесіть стилі з css/style.css у main.scss: використайте змінні, вкладеність не глибше трьох рівнів, міксин для медіазапитів і @each, що генерує бейджі для трьох спеціальностей. Підключайте частини лише через @use.
  3. Запустіть sass --watch scss/main.scss css/style.css. Переконайтеся, що сторінка виглядає так само, як до переходу на Sass, а в терміналі немає помилок і попереджень. Відкрийте css/style.css і знайдіть, на що перетворилися міксин і цикл.
  4. Підготуйте сайт за чек-листом: index.html у корені, відносні шляхи, назви файлів малими латинськими літерами без пробілів, заповнені <title> і <meta name="description">. Перевірте HTML у валідаторі W3C (ПР 13).
  5. Створіть на GitHub публічний репозиторій webdesign-lecture8 і завантажте в нього вміст папки (index.html, css, scss, зображення). У Settings → Pages оберіть Deploy from a branch, гілку main, папку /(root) і натисніть Save. Через кілька хвилин відкрийте сайт за посиланням Visit site.
  6. Відкрийте опублікований сайт на своєму телефоні та в DevTools на ширині 320 пікселів. Додатково (за бажанням) опублікуйте ту саму папку через Netlify Drop і порівняйте адреси та швидкість публікації.
